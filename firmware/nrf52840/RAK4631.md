# Pine on RAK4631, with optional Ethernet and PoE

Run a MeshCore repeater and a separate native command bot on a **RAK4631
WisBlock core** containing the RAK4630 nRF52840/SX1262 module. Add a
**RAK13800 W5100S Ethernet module** for a wired companion connection; its
optional **RAK19018 PoE module** supplies power through Ethernet. Use a
WisBlock base that supports those modules. This profile uses their upstream
wiring; another Ethernet chip or carrier needs its own board profile.

The bot supports personal notes and the native mesh commands. Notes,
identities, names, BLE settings and repeater preferences live in InternalFS.
Choose [XIAO or SenseCAP Solar Pine](README.md) for the Lua, Room and packet
program profiles, which use external QSPI storage.

## Build and install

Install PlatformIO and Python 3.12 or later, then work from the repository root. Choose
one of these profiles:

| Hardware and use | Normal update | First installation |
| --- | --- | --- |
| RAK4631 radio with optional BLE companion | `nrfmast_rak4631` | `nrfmast_rak4631_init` |
| RAK4631 + RAK13800 Ethernet companion | `nrfmast_rak4631_rak13800` | `nrfmast_rak4631_rak13800_init` |

For a new board, select the matching `_init` profile. It creates missing
repeater and bot identities. It initializes InternalFS only when its entire
storage region is erased; existing unreadable data stops startup for recovery.
Existing readable identity records stay unchanged, including after an interrupted
first installation. Use the normal profile for subsequent updates: missing
identity records stop startup instead of generating replacements.

Before building, set `LORA_FREQ`, `LORA_BW`, `LORA_SF`, `LORA_CR` and
`LORA_TX_POWER` in `[env:nrfmast_rak4631_rx]` in `platformio.ini` to your
mesh's legal PHY. The source defaults are 912.525 MHz, 250 kHz, SF7, CR5 and
2 dBm. The RF profiles can advertise after startup.

```sh
PINE_ENV=nrfmast_rak4631_rak13800_init
make -C firmware/nrf52840 build ENV="$PINE_ENV" PIO_JOBS=2
APP="$PWD/firmware/nrf52840/.build/upstream/.pio/build/$PINE_ENV"
python3 firmware/nrf52840/ble_field.py package --board rak4631 \
  --zip "$APP/firmware.zip"
```

The build selects the RAK4631's **S140 6.1.1 SoftDevice** and application start
**0x26000**. Check your installed RAK bootloader and SoftDevice before copying
an image; XIAO and SenseCAP Solar images use a different layout. Retain the
installed bootloader. These application files contain neither a bootloader
nor a SoftDevice update.

Connect the board by USB and double-press RESET to open its UF2 drive. Read
`INFO_UF2.TXT` on that drive and confirm it identifies this RAK4631 and the
matching SoftDevice. Copy the selected `firmware.uf2` to that exact drive:

```sh
RAK_DRIVE='/media/USER/REPLACE_WITH_RAK_UF2_DRIVE'
cat "$RAK_DRIVE/INFO_UF2.TXT"
cp "$APP/firmware.uf2" "$RAK_DRIVE/"
```

**Do not erase flash or install a combined bootloader/SoftDevice image to
update Pine.** App-only UF2 and Legacy DFU packages leave InternalFS and the
installed bootloader in place. Keep a copy of valuable node state before
maintenance. The XIAO-specific `hardware.py` upload commands are for XIAO;
use this RAK UF2 path.

## Configure the radio

Connect a suitable antenna before powering the radio. Open its USB serial
console at **115200 baud**. Set legal radio parameters matching your mesh,
choose node names and set an administrator password:

```text
set name RAK-Relay
set bot.name RAK-Bot
password YOUR_ADMIN_PASSWORD
set radio 912.525,250,7,5
set tx 2
reboot
```

The example PHY is also the build default. Substitute your mesh's frequency
in MHz, bandwidth in kHz, spreading factor, coding rate and legal TX power.
The repeater and bot share that radio profile and retain separate identities.
The password command echoes its result; keep your serial session private.
Use `get radio`, `get bot.name`, `bot state` and `stats radio` to read the
running configuration. `bot state` reports `notes_backend=internalfs`.
Send the bot an encrypted `!help` DM from another companion radio to see its
commands. [Native notes](STATE-BLE.md#personal-notes-over-rf) explains note
ownership, key names, quotas and timestamp handling. RAK uses the same note
format and limits, stored in InternalFS rather than an external-QSPI journal.

## Connect over Ethernet

For the RAK13800 profile, attach Ethernet before powering up. DHCP supplies
the address; look for `ETH: IP Address` in the USB console or find the logged
Ethernet MAC in your router's DHCP leases. Reserve that address in DHCP for
reliable remote access. The network task handles DHCP, lease renewal and socket traffic separately
from radio forwarding and USB administration.

Connect the MeshCore iOS or Android app to that address on **TCP port 5000**.
This is the bot's companion connection, using its existing public identity.
One TCP client can connect at a time; a new connection replaces the previous
client. Repeater administration remains available through USB or authenticated
MeshCore administration over RF.

**Keep port 5000 on a trusted LAN or VPN:** companion TCP has no login or
transport encryption. It allows bot messaging and contact operations; it does
not grant repeater administration or private-key export. This profile has no
Telnet administration listener or web dashboard.

For a network without DHCP, the upstream Ethernet transport also accepts
`ETHERNET_STATIC_IP`, `ETHERNET_STATIC_GATEWAY`, `ETHERNET_STATIC_SUBNET` and
`ETHERNET_STATIC_DNS` as comma-separated address octets in build flags. Set
all four together in your private PlatformIO configuration and rebuild.

## Update nearby over BLE

Provision a saved BLE PIN through USB before installing remotely:

```text
set bot.ble.pin YOUR_SIX_DIGIT_PIN
set bot.ble on
reboot
```

Choose 100000–999999. On the Ethernet profile, the companion app uses TCP;
BLE provides the guarded firmware-update service. On the radio-only profile,
BLE also provides the paired companion connection.

Use the normal profile's checked app-only `firmware.zip`. From authenticated
repeater administration, run `get update`, then `start ota confirm`, and use
a Nordic Legacy DFU phone tool with the saved PIN. The update-entry window is
120 seconds. Keep power and the phone connection available through the
single-bank transfer; an interrupted transfer can require USB recovery.
[BLE field updates](BLE-FIELD-UPDATE.md) covers arming and recovery. RAK package
checks must use `--board rak4631`; the XIAO signed Lua update helper selects a
different application layout.
