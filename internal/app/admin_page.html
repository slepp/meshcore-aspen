Host administration

Monitor host roles and configure the native bot through its existing owner console. The companion radio's WiFi, firmware, physical sensors and identities belong to that radio, not this host.

Use localhost or a trusted TLS tunnel. Plain HTTP exposes the login credential, session and source/private data. An authenticated session grants owner access to bot settings, source and scoped backups. Reusing a role admin password also exposes that role's credential if HTTP is intercepted. Never paste private keys or service credentials into the console.

Disconnected

Login sends this credential once; subsequent requests use a random ten-minute session retained only in this tab. Four sessions and five login attempts per minute are allowed.

Roles and capabilities



Host role selection, listeners, MQTT and PHY authority remain in the operator's host configuration; activate those changes with an explicit service restart.
This page never overwrites that configuration. Running state is shown below; bot settings and source save through native durable helpers.


Relay and room role configuration






Role owner controls are enabled only when the host provides its existing role command adapter.


These commands use the running relay/room engine and its durable save helpers, not a second configuration store.
Names preserve identities. Read help for path-hash and advert intervals; native bounds remain authoritative.
Shared PHY, credentials, identities, ACLs and restart are unavailable here. Companion settings remain in the native app/CLI.


In the scoped role console, use region def can ab edm, then
region home ab and region save. Read region
to check the tree and ab^ home marker. Home does not select an outgoing scope;
use region default ab only when that role should originate ab-scoped floods.

Scoped owner console



Bot diagnostics, grants, source and scoped data export/stage/restore commands use the existing owner API.
Backups contain private values; use mast_cli.py --unix-socket … data-export/data-restore for verified files.
There is no whole-host import/export. Role identities, private keys, passwords, channel provisioning and radio retuning are not accepted here.


The native MeshCore app connects to the companion TCP endpoint for chats, contacts, channels and role-specific radio administration.
